━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  WHY CRITICAL:
  The current whitelist page calls identityRegistry.registerIdentity() but
  ERC-3643 spec requires each investor to have a deployed ONCHAINID smart
  contract (ERC-734/ERC-735) with verified claims. Without this, the
  compliance contract's canTransfer() will reject ALL transfers regardless
  of whitelist status. This is the foundational gap that blocks everything.

  1.1 — Smart Contracts
  ─────────────────────
  - Install @onchain-id/solidity: npm install @onchain-id/solidity
  - Deploy IdFactory contract (creates ONCHAINID per investor)
  - Deploy platform ClaimIssuer contract (acts as Trusted Issuer)
  - Add env vars: CLAIM_ISSUER_ADDRESS, ID_FACTORY_ADDRESS,
    CLAIM_ISSUER_PRIVATE_KEY
  - Register ClaimIssuer in TrustedIssuersRegistry for each token suite
  - Define claim topics in ClaimTopicsRegistry:
    Topic 1 = KYC_APPROVED
    Topic 2 = COUNTRY_OF_RESIDENCE (ISO numeric code)
    Topic 3 = INVESTOR_CLASSIFICATION (retail/accredited/institutional)
    Topic 4 = ACCREDITED_STATUS

  1.2 — Database Migration
  ────────────────────────
  New migration: 006_identity_tables.sql
  - Add to tenant schema: onchain_identities table
    Columns: id, user_id, identity_contract_address, chain_id,
    claim_topics_issued JSONB, registered_token_ids JSONB,
    deployed_at, created_at, updated_at
  - Add identity_contract_address column to users table
  - Add claim_issuer_address to tokens table (which ClaimIssuer is trusted)

  1.3 — API: New Identity Module
  ────────────────────────────────
  Create: apps/api/src/modules/identity/
    identity.module.ts
    services/
      identity-deployment.service.ts
        - deployIdentity(userId, walletAddress, chainId): calls IdFactory
          createIdentity(walletAddress) via blockchain-service
        - getOrDeployIdentity(userId, walletAddress, chainId): idempotent
      claim-issuance.service.ts
        - issueClaim(identityAddress, claimTopic, claimData): signs claim
          with ClaimIssuer private key, calls identity.addClaim()
        - issueKycClaims(identityAddress, kycData): issues all 4 claims at once
        - revokeClaim(identityAddress, claimId): on KYC expiry or rejection
      identity-registry.service.ts
        - registerInToken(identityAddress, walletAddress, countryCode,
          tokenId): calls identityRegistry.registerIdentity() on-chain
        - isRegistered(walletAddress, tokenId): check registration status
    controllers/identity.controller.ts
      GET  /identity/me               — investor's ONCHAINID status
      POST /identity/deploy           — deploy ONCHAINID for user
      POST /identity/register-in-token — register in specific token IR
      GET  /identity/:tokenId/status  — check if user eligible for token
    entities/onchain-identity.entity.ts

  ─────────────────────────────
  File: apps/api/src/modules/payments/controllers/webhook.controller.ts

    Step 1: Verify Stripe webhook signature (STRIPE_WEBHOOK_SECRET)
